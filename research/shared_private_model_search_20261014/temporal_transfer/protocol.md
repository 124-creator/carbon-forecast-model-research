# Frozen synthetic protocol 2026-10-14
Before training, fixed seeds 17,29; same pilot.data and 340 parameter shared/private MLP, no market files. Six search queries total. No threshold search or per-block no-harm gate.
Split: core [0,48), internal chronological transfer-tail [48,64), external checkpoint validation [64,128), test [128,512). Original pilot normalization uses [0,64); explicitly redo normalization using core only. Features and targets retain original pilot simultaneous-response synthetic meaning: this is temporal generalization, not a certified one-step-ahead forecast.
Methods: SP, PCGrad, adaptive_weights, temporal_transfer, random_tail, private_only. All receive identical core gradients and identical reserved inner-information budget. 1200 steps, learning rate .04, four core task gradients plus four inner task gradients per step (8 objective gradient calls each), no retries, total cap 600 seconds. Dummy inner calls for controls prevent information-budget mismatch; not equal FLOPs. Evaluate outer validation every 20 steps; independently save whole parameter vector for each task's best checkpoint. Test only after fitting.
Candidate: inner-tail gradients H and core gradients G restricted to shared coordinates. A_ij=H_i dot G_j predicts recipient-i inner loss decrease from donor-j update. Donor weights softmax(mean_i A_ij / RMS(A)); shared update weighted donor gradients; private updates uniform. No safety gate, no shared rejection. This is deliberately a validation-gradient adaptive weighting route, NOT claimed first or structurally novel. adaptive_weights uses the SAME A and weights but weights all coordinates, isolating shared-only localization. random_tail substitutes fixed random 16 core points for chronological inner tail, keeping the identical eight-gradient-call budget. It intentionally does not consume chronological tail labels. private_only disables shared update.
Contribution conditions: outperform PCGrad and same-information adaptive weighting in both seeds, chronology beats random-tail, preserve no-common task; robust additional scenarios and theoretical distinction from existing validation reweighting required for novelty. Failure stops this route.
