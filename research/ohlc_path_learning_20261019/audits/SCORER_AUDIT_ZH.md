## 冻结后的评分代码改动记录

### A. 验证完全同分的严格校验

在首次正式市场评分前，独立复核者发现评分器已检查所选同信息点控制的验证 MSE 为最小值，但没有额外强制完全同分时的模型名称字典序。协议和 runner 已有这一固定规则。

因此在 `read_fold` 中增加一个断言：

```python
expected_selected = min(POINT_CONTROLS, key=lambda family: (scores[family], family))
require(selected == expected_selected, "Validation baseline violates the fixed exact-tie name ordering")
```

此改动已先向主实验负责人说明，随后在正式评分前实施。它收紧元数据审计，不重新选择模型、不改预测、不改误差汇总、不改 bootstrap、不改门槛。

### B. 本地输入路径保护的误报修复

首次正式评分在读取市场数值前，以 `Observation/forecast inputs must stay outside a Git worktree` 中止。祖先路径标记存在性的启发式判断产生误报；分别在 `/tmp/carbon-path-local` 和 `/tmp/carbon-path-run` 运行 Git 的工作树查询，均确认它们不属于 Git 工作树。

已先报告此失败，随后将 `outside_git` 改为执行 `git -C <path> rev-parse --show-toplevel`，由 Git 判断真实工作树。输入仍必须在 Git 工作树之外；仅修复环境识别，不移入或导出任何原始数据。失败发生于标签/价格读取及统计之前，没有产生市场分数或部分结果。该修复不改变统计设计、预测、指标、bootstrap或门槛。

### C. 三个相同预测求平均时的浮点等值保留

首次成功评分已得到候选整体 STOP 的结论，但 Q1/Q3 的零轮模型与 RW 完全相同，直接计算三个 seed 之和再除以三产生机器浮点尾差，折级相对 MSE 分别为 `0.9999999999999999`、`0.9999999999999997`，使严格 `<1` 的胜出数错误地包含两个数学上相同的预测。这一问题在读取首轮正式汇总后发现，并立即向负责人报告。

在不改变等权算术均值定义的前提下，将其实现改为：`reference + mean(seed - reference)`。当所有 seed 相同，差为精确零，返回原预测；其余情形仍为代数相同的等权均值。新增数值检查包含 `0.1` 等易出现浮点求和尾差的相同输入，必须精确保留。

未增加或放宽胜出阈值，未作结果择优舍入；该修复消除两个虚假胜出，使实际胜出折数为1/6。原始预测、训练、验证选择、CI抽样规则和判据保持不变，整体 STOP 结论不变。完整聚合文件随后由修复后的评分器从相同原始输入重新生成。

## 正式评分范围及边界

独立评分器不导入模型、runner 或特征管线。它从本地原始 P/H/L 重构真值、共同起点及训练固定分母，核对数据／预测／权重字节哈希、代码指纹、成熟边界、验证选择和范围样本的有序嵌套。

价格主指标使用保存的解析／确定性均值；辅助 ES 对各 seed 的128条有限样本分别计算，再平均 seed。只输出聚合 CSV/JSON，逐起点数据、价格、预测、loss、样本与 bootstrap抽样均不入仓库。

成熟边界核验同时依赖静态代码审计与保存收据，不等于独立运行时数据访问追踪。仅凭保存的九维摘要也不能重建未导出的完整日级样本路径；解析均值和模型动力学已由单独的模型审计负责。
